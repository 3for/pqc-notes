# Lamport Signature（Lamport 一次性签名）

Lamport Signature 是最基础的基于哈希的数字签名方案之一，也是理解 WOTS+、XMSS、SPHINCS+ 和 NIST SLH-DSA 的重要起点。

它由 Leslie Lamport 在 1979 年提出，核心思想非常简单：

签名者预先生成两组随机秘密值，每签署消息摘要中的一个 bit，就公开对应的一个秘密值；验证者通过哈希确认这些秘密值与公钥匹配。

它最大的特点是：

- 不依赖 RSA、ECDSA 或格密码的数学困难问题。
- 主要依赖哈希函数的单向性。
- 能抵抗已知的 Shor 算法攻击。
- 只能安全地使用一次，因此属于 One-Time Signature（OTS，一次性签名）。

## 1. Lamport 签名如何工作？

假设消息摘要只有 4 bit：

$$
H(M)=1010
$$

为了签署这 4 bit，首先生成 4 对随机秘密值：

| Bit 位置 | 私钥 0            | 私钥 1            | 消息 Bit | 签名选择            |
| ------ | --------------- | --------------- | ------ | --------------- |
| 1      | $sk_{1,0}$ | $sk_{1,1}$ | 1      | $sk_{1,1}$ |
| 2      | $sk_{2,0}$ | $sk_{2,1}$ | 0      | $sk_{2,0}$ |
| 3      | $sk_{3,0}$ | $sk_{3,1}$ | 1      | $sk_{3,1}$ |
| 4      | $sk_{4,0}$ | $sk_{4,1}$ | 0      | $sk_{4,0}$ |

因此，摘要 $1010$ 对应的签名为：

$$
\sigma=(sk_{1,1},sk_{2,0},sk_{3,1},sk_{4,0})
$$

这里用 4 bit 简化演示，实际方案通常签署更长的消息摘要。

## 2. 密钥生成（KeyGen）

对于一个 $n$-bit 消息摘要，每个 bit 需要两个随机秘密值：

$$
sk_{i,0},sk_{i,1}\in\{0,1\}^{n}
$$

其中：

$$
i=1,\ldots,n
$$

私钥总共包含 $2n$ 个随机值。

对应公钥是这些秘密值的哈希：

$$
pk_{i,b}=H(sk_{i,b}),\qquad b\in\{0,1\}
$$

因此：

$$
SK=\{sk_{i,0},sk_{i,1}\}_{i=1}^{n}
$$

$$
PK=\{H(sk_{i,0}),H(sk_{i,1})\}_{i=1}^{n}
$$

## 3. 签名（Sign）

假设：

$$
H(M)=b_1b_2\cdots b_n
$$

签名者按照每个 bit 的值，选择对应的秘密值：

$$
\sigma=(sk_{1,b_1},sk_{2,b_2},\ldots,sk_{n,b_n})
$$

签名中只公开每对秘密值中的一个。

## 4. 验签（Verify）

验证者重新计算消息摘要：

$$
H(M)=b_1b_2\cdots b_n
$$

然后逐项检查：

$$
H(\sigma_i)\stackrel{?}{=}pk_{i,b_i}
$$

如果全部成立，签名有效。

验证者不需要知道私钥中未公开的秘密值。

## 5. 为什么 Lamport 只能签名一次？

这是理解 Lamport Signature 最重要的地方。

假设同一密钥签署了两条不同的消息：

```
Message A: 1010
Message B: 0110
```

观察两个签名公开的秘密值：

| 位置 | A | B | 已公开的秘密值 |
| -- | - | - | ------- |
| 1  | 1 | 0 | 两个都公开   |
| 2  | 0 | 1 | 两个都公开   |
| 3  | 1 | 1 | 只公开 1   |
| 4  | 0 | 0 | 只公开 0   |

对于前两个 bit，攻击者已经获得了对应的两份秘密值，可以自由选择签名 0 或 1。

在这个简化示例中，攻击者甚至可以组合出：

```
Message C: 0010
```

对应的签名材料全部可以从 A、B 的签名中获取。

这说明：重复使用 Lamport 私钥，会不断暴露更多秘密值，破坏一次性签名的安全保证。 不过，重复签名并不意味着在所有实际参数下都能立即伪造任意消息。

## 6. Lamport 的密钥和签名有多大？

假设使用 SHA-256，消息摘要为 256 bit，每个秘密值也是 256 bit。

| 数据 | 计算                         | 大小       |
| -- | -------------------------- | -------- |
| 私钥 | $2\times256\times32$ B | 16,384 B |
| 公钥 | $2\times256\times32$ B | 16,384 B |
| 签名 | $256\times32$ B        | 8,192 B  |

这只是经典 Lamport OTS 的直接表示，未使用种子派生、Merkle 公钥压缩等优化。

它的主要缺点就是密钥大、签名大，而且只能安全签署一条消息。

## 7. Lamport 与 WOTS+、XMSS、SLH-DSA 的关系

| 方案          | 如何改进                         | 解决什么问题               |
| ----------- | ---------------------------- | -------------------- |
| Lamport OTS | 每个消息 bit 公开一个秘密值             | 最基础的一次性签名            |
| WOTS+       | 使用哈希链和 Winternitz 编码         | 缩小一次性签名与公钥           |
| XMSS        | 使用 Merkle Tree 认证多个 WOTS+ 公钥 | 一个顶层公钥支持多次签名，但需要维护状态 |
| SLH-DSA     | FORS + WOTS+ + Hypertree     | 无需维护全局一次性密钥索引        |

严格来说，SLH-DSA 并不是直接把 Lamport 签名放进多层树，而是采用了更复杂的哈希签名组件。

下一步最值得研究的是：WOTS 为什么能将 Lamport 的 256 组签名元素缩减到约 67 组，以及为什么必须引入 Checksum。 这是理解 SLH-DSA 的关键一步。
